# Модель повторной покупки

## Назначение

Учебный скоринг **известных клиентов**, имеющих покупки до даты прогноза: есть ли хотя бы одна покупка за следующие 90 дней. Скор не является оценкой причинного эффекта скидки; калибровка вероятностей не проводилась. Это прототип для обсуждения методологии и интеграции, а не готовая производственная CRM-система.

## Данные и признаки

Источник — [UCI Online Retail](https://doi.org/10.24432/C5BW33), CC BY 4.0, транзакции британского магазина с декабря 2010 по декабрь 2011. После очистки: 392 692 строки, 18 532 заказа, 4 338 клиентов. В данных много оптовых покупателей; перенос на современный магазин требует отдельной проверки.

Признаки рассчитываются строго до среза: давность, число заказов, сумма и средний/максимальный чек, число товаров в заказе, активные месяцы, уникальные товары, объём покупок, средний интервал между заказами, стаж клиента и наиболее частая страна его прошлых заказов. Имя клиента, даты среза и целевая переменная в модель не поступают. Интервалы измеряются в днях; средний интервал допускает null для единственного заказа.

Отбор строк: идентификатор клиента присутствует; отмены, неположительные количество/цена и полные дубликаты исключены. Поэтому положительная выручка после очистки не является полной бухгалтерской нетто-выручкой с возвратами.

## Хронология проверки

| Этап | Даты срезов | Когда заканчиваются ответы |
| --- | --- | --- |
| Обучение для выбора модели | 1 марта 2011 | 30 мая 2011 |
| Валидация | 1 июня 2011 | 30 августа 2011 |
| Финальное обучение после выбора | 1 марта, апреля, мая, июня 2011 | Не позже 30 августа 2011 |
| Отложенный тест | 1 сентября 2011 | 30 ноября 2011 |

Условие для каждого обучающего примера: `train_cutoff + 90 дней <= next_prediction_cutoff`. Признаки дополнительно ограничены прошлым собственного среза. Июльские и августовские срезы не попадают в финальное обучение: их 90-дневные ответы ещё не известны на 1 сентября. Сам тест полностью наблюдён к концу исходного датасета.

Выбор между Logistic Regression и Random Forest сделан по ROC-AUC валидации. Параметры моделей и порог 0,5 фиксированы в коде; тест не используется для выбора победителя или настройки порога. Предобработка чисел и категорий обучается внутри собственного sklearn Pipeline каждой модели.

## Пересчитанные результаты

| Модель | Validation ROC-AUC | Test ROC-AUC | Test F1 | Test Precision | Test Recall |
| --- | ---: | ---: | ---: | ---: | ---: |
| Logistic Regression | 0,7510 | 0,7353 | 0,6705 | 0,7735 | 0,5917 |
| Random Forest | **0,7545** | **0,7456** | **0,6983** | 0,7421 | **0,6593** |

Выбран Random Forest. В тесте 3 317 клиентов; в финальном обучении 8 968 строк по 2 718 известным клиентам. Полные значения и размеры находятся в `data/processed/temporal_validation.json`, таблицы — в `model_metrics.csv` и `validation_metrics.csv`. Прежние показатели исходного разбиения заменены; напрямую приписывать разность метрик только одной причине нельзя, поскольку изменились схема проверки и настройки baseline.

## Ограничения

- История короткая: один валидационный срез и один финальный тест. Нужны другие периоды и внешние данные для проверки устойчивости.
- Клиенты повторяются в месячных срезах, наблюдения зависимы. Это соответствует прогнозу для известных клиентов; качество на новых клиентах здесь не оценивалось.
- Перекрытие обучающих целевых окон между собой допустимо по доступности информации, но создаёт зависимость строк. Все они завершаются до следующей контрольной даты.
- Скор требует проверки калибровки перед интерпретацией как точной вероятности. Приоритет контакта не равен ожидаемому дополнительному эффекту контакта.
- Эффект кампании, бизнес-прибыль, устойчивость к сдвигам и нагрузочная способность сервиса не измерялись.

## Артефакт и API

`models/repeat_purchase.joblib` содержит фактически обученный pipeline; `metadata.json` — контрольную сумму, версию контракта, зависимости и отчёт проверки. API проверяет хеш перед загрузкой, требует все обязательные признаки, отвергает неизвестные поля, нечисловые/нефинитные значения и логически несовместимые профили. Новый неизвестный текстовый country допустим благодаря OneHotEncoder(handle_unknown="ignore").

Загружать joblib нужно только из доверенного источника. Используйте версии из `uv.lock` и опубликованный Dockerfile. Воспроизведение: `uv run python -m retail_repeat_analysis.download_data`, затем `uv run python src/build_assets.py`.
