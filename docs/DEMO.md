# Демонстрация проекта за пять минут

## Запуск готовой версии

```bash
docker compose up --build -d --wait
python scripts/smoke_services.py
```

Откройте http://localhost:8501 и http://localhost:8000/docs. Таблицы и обученный pipeline входят в репозиторий. Сырой UCI CSV нужен только для пересборки анализа и модели.

Без Docker: `uv sync --frozen --extra dev`; в отдельных терминалах `uv run streamlit run app.py` и `uv run uvicorn retail_repeat_analysis.api:app --host 127.0.0.1 --port 8000`.

## Сценарий показа

1. **Продажи.** На полном периоде: 18 532 заказа и 4 338 клиентов. Выберите France и убедитесь, что показатели изменились. Пустой период даёт понятное сообщение.
2. **RFM.** Вернитесь ко всем странам. Покажите доли клиентов и выручки сегмента «Чемпионы»; выгрузите клиентскую таблицу CSV. Объясните дату среза: история берётся до конечной даты фильтра.
3. **Когорты.** Покажите тепловую карту. Отличите наблюдённый ноль от пустого будущего/неполного месяца. Когорты строятся на всей доступной истории до конечной даты.
4. **Эксперимент.** Поменяйте исходную конверсию или MDE и покажите изменение выборки. Синтетическая проверка мощности не является результатом реальной рассылки. Полный дизайн находится в `AB_TEST_DESIGN.md`.
5. **Модель.** Покажите метрики отложенного среза и границы временной проверки. Random Forest выбран по валидации. Test ROC-AUC 0,7456, F1 0,6983; порог 0,5.
6. **API.** В `/docs` выберите POST /predict и вставьте `examples/predict_request.json`. Сравните ответ с `examples/predict_response.json`. Затем удалите обязательное поле или задайте отрицательный счётчик: ожидается 422.
7. **Проверки.** Откройте GitHub Actions и результаты автоматических тестов/контейнеров. Проверяемые ограничения времени и входов важнее голословного заявления о «готовности к продакшену».

## Что можно утверждать по опубликованному коду

- Реализован интерфейс Streamlit с фильтрами, сегментами, когортами и A/B-калькулятором.
- Подготовлен дизайн CRM-эксперимента с наблюдаемым baseline, выборкой и правилами решения.
- Пересчитаны модели по временной схеме с завершением целевых окон до следующего контрольного среза.
- Обученный pipeline опубликован, API проверяет входы и возвращает фактический скор.
- Приложение упаковано в Docker; запросы и интерфейс покрыты автоматическими тестами.

Эффект настоящей CRM-кампании, калибровка вероятностей, производственная нагрузка и эксплуатация в реальном бизнесе не заявляются. Реализация с помощью Codex сама по себе не заменяет понимание: перед встречей разберите признаки, разбиение и один запрос по коду.

## Основные файлы

| Файл | Что показать |
| --- | --- |
| `app.py` | Интерфейс, фильтры и вкладки |
| `src/retail_repeat_analysis/analytics.py` | Расчёт срезов и когорт |
| `src/retail_repeat_analysis/experiments.py` | Baseline, выборка и синтетическая симуляция |
| `src/retail_repeat_analysis/modeling.py` | Признаки, временное разделение, обучение и сохранение |
| `src/retail_repeat_analysis/api.py` | Контракт API, проверки и прогноз |
| `data/processed/temporal_validation.json` | Даты и измеренные метрики |
| `models/metadata.json` | Хеш и версия артефакта, зависимости |
| `tests/` | Проверки данных, временных окон, API и Streamlit |
